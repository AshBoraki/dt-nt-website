DTNT Privacy Notice

2. DTNT app data

DTNT processes network adapter details, nearby Wi-Fi names and radio identifiers, IP and MAC addresses, hostnames, service responses, saved Windows Wi-Fi profiles, and diagnostic results on your PC. Saved device labels, site inventory, speed-test history, settings, and exports also remain local unless you share them. The app does not automatically upload those inventories, saved Wi-Fi keys, device passwords, exports, or diagnostic logs to Denali Tech. Online activation and update checks operate separately, as described in section 3.

When you use the Profiles workspace, DTNT can read saved Windows Wi-Fi profile names, security labels, and saved keys from Windows so it can show the local profile state on that machine. Saved keys are shown or copied locally when you choose to reveal them, and they are not included in the DTNT profile export format by default.

When you save a device login in IP Scanner, its password is protected locally using Windows data protection for the current Windows account. Its username and identifying information, such as the device and site, are stored locally without that password protection. These login records are not included in DTNT job inventory exports. Revealing or copying a password exposes it on screen or to the Windows clipboard; clipboard history or synchronization, if enabled in Windows, can retain or share copied text.

When you run IP Scanner and related discovery workflows, DTNT can send ping, DNS, TCP-connect, ARP-assisted, and short HTTP(S) requests to the selected targets to identify responsive devices and likely web interfaces. DTNT may temporarily read headers and a small body snippet to classify a web interface; that body sample is not included in the standard export. DNS resolvers, target devices, and network operators can observe these requests. Use these tools only where you have authorization.

Local diagnostic logs can contain timestamps, component names, status messages, file paths, and exception details. Settings, logs, inventories, and exports are not all encrypted by DTNT. Protect your Windows account, devices, backups, and exported files, and review files before sending them to support.

3. Online app features and automatic requests

  • Pro activation: activating online sends your purchase email, activation code, random device identifier, and Windows computer name to Denali Tech's fulfillment service hosted on Cloudflare. The service stores order and device activation records to verify purchases and manage licensed seats. It returns a signed entitlement and device authentication token for local use. The random identifier is created by DTNT; it is not a hardware serial number.
  • License validation: after online activation, the app automatically checks the stored activation when it starts, sending the device identifier and authentication token. Successful validation updates the server's last-validation timestamp. Releasing this PC sends the identifier, token, and a release reason. Releasing a seat does not delete the order or its activation history.
  • Update checks: the app automatically requests release metadata from the DTNT website when it starts and can check again while running or when you select Check for updates. The hosting service receives the request's IP address and normal connection information. The update check does not upload your scan results. Microsoft separately processes Store installations and updates.
  • Speed tests: when you start a test, DTNT downloads test data from and uploads generated test bytes to speed.cloudflare.com. It does not upload your personal files for the speed test. Cloudflare receives your public IP address and connection information. Tests can transfer substantial data and use your network bandwidth.
  • Other tools and links: ping, traceroute, DNS, port checks, and web links contact their selected targets, your DNS provider, or the site opened in your browser. The receiving services process these requests under their own policies.

The activation and update hosts necessarily receive IP addresses and request metadata as part of providing their services. The app's local operation does not mean that it makes no internet requests.

The saved device authentication token is protected using Windows data protection for the current Windows account. Other local activation metadata, including your purchase email, device identifier, computer name, and timestamps, remains readable to processes that can access those files.
